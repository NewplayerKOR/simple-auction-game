> **제품 기준 버전:** v2.3.0  
> **다음 안정화 목표:** v2.3.1  
> **상태:** CONDITIONAL_APPROVAL

## 1. 문서 목적과 권위

이 문서는 제품이 제공해야 하는 사용자 가치와 게임 규칙을 정의한다. 구현 세부사항은 `.md/specs/` 문서와 TASK에서 관리한다.

- `APPROVED` 요구사항은 구현 기준으로 사용할 수 있다.
- `OPEN_DECISION` 요구사항은 결정 전 구현하지 않는다.
- 현재 구현·검증 상태는 `.md/specs/PROJECT_STATE.md`를 따른다.
- 작업 상태는 `.md/root/TASKS.md`를 따른다.
- 제품·기술·거버넌스 결정은 `.md/specs/DECISIONS.md`를 따른다.
- `DONE` 처리는 모든 역할군이 가능하며, DoD와 검증 증거를 충족해야 한다. 상세 규칙은 `.md/root/AGENTS.md`의 GOV-002를 따른다.

## 2. 제품 비전

플레이어가 제한된 자금으로 유물의 가치와 위험을 판단하고 AI 경쟁자와 경매하여 영구 컬렉션과 순자산을 성장시키는 웹 기반 경매 경제 시뮬레이션을 제공한다.

핵심 사용자 경험은 다음과 같다.

- 제한된 정보에서 가치와 위작 위험 판단
- 잉글리시·더치·비밀 봉투 방식의 서로 다른 긴장감
- 승리뿐 아니라 현금 보존과 장기 커리어 성장
- 복원·위탁 판매·시장 변동을 통한 사후 경제 활동
- 암시장의 고수익과 영구 디버프·경찰 위험 선택

## 3. 제품 범위

### 3.1 현재 포함

- 싱글플레이, 플레이어 1명과 AI 봇 3명
- 5라운드 경매 세션
- 영구 커리어와 LocalStorage 저장
- 5개 룸과 30종 아이템
- 잉글리시, 4R 비밀 봉투, 더치 경매
- 감정, 찬스 카드, 대출, 위작, 시너지
- 파산, 복원, 위탁 판매, 업적, 도감
- 암시장, 밀수품, 경찰 급습

### 3.2 현재 제외

- 실시간 멀티플레이
- 서버 권위형 자금·입찰 원장
- 실제 사용자 계정과 클라우드 저장
- 운영 DB와 실행 가능한 DB 마이그레이션
- 결제 또는 현금성 자산

## 4. 핵심 게임 요구사항

### REQ-CORE-001: 게임 세션

**상태: APPROVED**

- 한 게임은 기본 5라운드로 구성한다.
- 플레이어와 AI 봇 3명이 참여한다.
- 라운드 종료 시 낙찰자·가격·아이템을 정확히 한 번 확정한다.
- 게임 종료 시 현금, 진품 가치, 시너지, 대출을 반영해 순위를 계산한다.

### REQ-CORE-002: 경제 보존

**상태: APPROVED / DEC-001**

- 경매 참가와 종료만으로 설명되지 않는 현금이 생성되거나 소실되어서는 안 된다.
- 커리어 현금과 세션 현금은 동일한 자금 원장으로 취급한다.
- 입장료 차감 후 커리어 현금을 세션 시작 잔액으로 사용한다.
- 정상 종료 시 기존 커리어 현금에 종료 잔액을 더하지 않고, 대출 상환과 종료 디버프를 반영한 최종 세션 잔액으로 교체한다.
- 정산 공식은 파산·룸 게이팅·위탁 판매와 동일한 자금 원장을 사용해야 한다.

### REQ-CORE-003: 영속화

**상태: APPROVED**

- 커리어 현금, 순자산, 보관 아이템, 업적, 티켓, 파산 상태를 LocalStorage에 저장한다.
- 저장 데이터가 손상되면 안전한 초기 상태로 복구한다.
- 제품 데이터 변경 시 저장 버전과 마이그레이션 규칙을 기록한다.

## 5. 경매 방식

### REQ-AUC-001: 잉글리시 호가

**상태: APPROVED**

- 현재 최고가보다 높은 입찰만 허용한다.
- 잔액보다 높은 입찰을 거부한다.
- 종료 직전 입찰은 앤티 스나이핑 규칙에 따라 시간을 연장한다.
- 최고 입찰자가 없으면 유찰한다.

### REQ-AUC-002: 4R 비밀 봉투

**상태: APPROVED**

- 제한시간은 15초다.
- 미입력 또는 잔액 부족 제출은 `0`, 즉 자동 기권으로 확정한다.
- 플레이어와 봇의 제출 결과는 한 번만 생성한다.
- 타임아웃 또는 수동 제출 후 타이머를 종료하고 결과 공개 상태로 전이한다.
- 공개 중 결과가 바뀌거나 중복 정산되어서는 안 된다.

### REQ-AUC-003: 더치 역경매

**상태: APPROVED (STAB-001 재검증 완료)**

- 가격은 시작가에서 바닥가까지 시간 기반으로 하락한다.
- 유효한 구매자 중 원자적으로 한 명만 낙찰한다.
- 잔액과 상태를 검증한 뒤 클레임 락을 확정한다.
- AI는 플레이어에게 숨겨진 실제 진위·가치를 직접 사용하지 않는다.
- 바닥가 처리와 최종 구매 기회 시간은 `.md/specs/ARCHITECTURE.md` 계약으로 명시한다.

## 6. 룸과 아이템

### REQ-ROOM-001: 룸 구성

**상태: APPROVED**

| 룸 | 최소 순자산 | 입장료 |
| :--- | ---: | ---: |
| 브론즈 | $0 | $0 |
| 실버 | $15,000 | $1,000 |
| 골드 | $60,000 | $5,000 |
| 다이아몬드 | $200,000 | $20,000 |
| 암시장 | $100,000 또는 VIP 티켓 | $10,000 |

암시장 입장료 $10,000은 현재 구현·테스트 기준이며 제품 정책 재검토 시 결정 로그로 변경한다.

### REQ-ITEM-001: 마스터 아이템

**상태: APPROVED / DEC-005**

- 일반 4개 룸에 각 6종, 총 24종을 배치한다.
- 암시장에 밀수품 6종을 배치한다.
- 전체 마스터 아이템 수는 30종이다.
- 한 게임에서는 해당 룸의 6종 중 5종을 중복 없이 선택한다.

## 7. 암시장

### REQ-BM-001: 진입과 티켓

**상태: APPROVED / DEC-004**

- 순자산 $100,000 이상 또는 블랙 VIP 티켓으로 해금한다.
- 골드 또는 다이아몬드 룸 5라운드 정상 완주 시 순위와 관계없이 티켓 1장을 지급한다.
- `ach-blind-master`를 최초 해금할 때 티켓 1장을 지급하며 중복 지급하지 않는다.
- 브론즈·실버·암시장 승리, 탈출, 체포, 중도 종료에는 티켓을 지급하지 않는다.
- 순자산 조건을 만족하지 못해 티켓으로 입장할 때 티켓 1장을 사용한다.
- 순자산 조건을 이미 만족하면 티켓을 사용하지 않는다.

### REQ-BM-002: 밀수품 저주

**상태: APPROVED (STAB-001 재검증 완료)**

- 밀수품 6종은 각각 문서화된 영구 디버프를 가진다.
- 데이터에 설명 문자열만 존재하는 것은 구현 완료로 인정하지 않는다.
- 각 디버프는 획득, 게임 종료, 대출, 복원, 시장 변동 등 해당 행동에서 검증되어야 한다.

### REQ-BM-003: 경찰 급습

**상태: APPROVED / DEC-002, DEC-003**

- 암시장 라운드에서 기본 15% 확률로 발생한다.
- 플레이어는 5초 안에 탈출 또는 뇌물을 선택할 수 있다.
- 탈출하면 현재 미확정 아이템을 포기하고, 이미 확정된 거래를 부분 정산한 뒤 로비로 돌아간다.
- 뇌물 선택은 `$5,000 + 현재 아이템 startingBid`를 한 번 차감하고 현재 아이템을 단독 낙찰한다.
- 뇌물 총비용보다 현금이 부족하면 뇌물 선택을 비활성화한다.
- 시간 초과 체포 시 세션 유동 현금을 전액 몰수하여 커리어 현금을 0으로 저장한다.
- 체포 세션에서 획득한 아이템은 영구 보관함에 커밋하지 않지만 기존 영구 보관함과 업적은 유지한다.
- 체포는 플레이 횟수에 포함하지만 승리·정상 완주·티켓 보상에는 포함하지 않는다.
- 모든 결과는 커리어 저장소에 반영되고 새로고침 후에도 유지되어야 한다.

## 8. 비기능 요구사항

### REQ-NFR-001: 무한 정지 방지

- 모든 타이머 상태는 정상 종료, 타임아웃 또는 안전 폴백을 가진다.
- 중복 클릭·중복 타이머·재진입으로 같은 결과가 여러 번 확정되지 않는다.

### REQ-NFR-002: 접근성

- 핵심 게임 흐름은 키보드로 조작할 수 있어야 한다.
- 모달은 의미 있는 이름, `dialog` 의미, 포커스 이동·복귀를 제공해야 한다.
- 텍스트와 핵심 금액 정보는 충분한 대비를 가져야 한다.

### REQ-NFR-003: 성능

- 초기 로딩 자산 예산을 릴리즈 전에 정의한다.
- 화면에 필요한 이미지 크기와 포맷을 최적화한다.
- 원본 에셋과 런타임 에셋을 구분한다.
