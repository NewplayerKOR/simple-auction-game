## 승인 결정 상세

### DEC-001: 커리어 현금 정산 모델

- **상태:** APPROVED
- **결정일:** 2026-08-21
- **결정자:** PM
- **문제:** 커리어 현금을 세션 시작 자금으로 사용하면서 종료 잔액을 기존 커리어 현금에 다시 더하면 설명되지 않는 현금이 생성된다.
- **결정:** 커리어 현금과 게임 세션 현금은 동일한 자금 원장으로 취급하고, 정상 종료 시 기존 금액에 더하지 않고 최종 세션 잔액으로 교체한다.
- **정산 순서:**
  1. 입장 전에 `careerCash_before`를 확인한다.
  2. 입장료를 한 번 차감하여 `sessionCash_start = careerCash_before - entryFee`로 시작한다.
  3. 입찰, 감정, 대출, 보조금, 뇌물 등 모든 게임 내 현금 변화를 세션 원장에 한 번만 반영한다.
  4. 정상 종료 시 대출 상환과 게임 종료 디버프를 반영한 `sessionCash_final`을 계산한다.
  5. `careerCash_after = sessionCash_final`로 교체한다.
  6. `careerNetWorth_after = careerCash_after + 영구 보관함 평가액`으로 다시 계산한다.
- **중도 종료:** 탈출은 이미 확정된 세션 거래를 반영해 부분 정산하고, 체포는 DEC-003을 우선 적용한다.
- **검토한 대안:** 기존 현금에 종료 잔액 합산, 별도 참가 자금·순손익 모델.
- **선택 이유:** 현재 게임은 커리어 현금 전체를 세션 가용 현금으로 사용하므로 종료 잔액 교체가 가장 단순하고 자금 보존을 검증하기 쉽다.
- **필수 검증:** 무입찰·전부 유찰 게임, 입장료만 지불한 게임, 대출 사용, 음수 잔액, 새로고침 후 잔액.
- **영향:** REQ-CORE-002, STAB-001/WP-01.

### DEC-002: 경찰 뇌물과 단독 낙찰 비용

- **상태:** APPROVED
- **결정일:** 2026-08-21
- **결정자:** PM
- **문제:** 고가 밀수품을 뇌물 $5,000만으로 획득하면 암시장 경제가 붕괴하고, PRD의 “뇌물 후 최저가 낙찰” 표현도 충족하지 못한다.
- **결정:** 뇌물 선택의 총 현금 차감액은 `bribeCost $5,000 + currentItem.startingBid`다.
- **행동 계약:**
  - 플레이어가 두 비용의 합계를 보유한 경우에만 선택할 수 있다.
  - 뇌물 $5,000과 아이템 시작가를 각각 한 번 차감한다.
  - 봇 경쟁을 종료하고 현재 아이템을 플레이어에게 단독 낙찰한다.
  - 경매 방식이 잉글리시 또는 더치인지와 관계없이 경찰 급습 특례 가격은 `startingBid`를 사용한다.
  - 잔액이 부족하면 뇌물을 비활성화하고 탈출 선택은 유지한다.
- **검토한 대안:** $5,000만 총비용, $5,000 + 더치 바닥가, $5,000 + 현재 호가.
- **선택 이유:** 시작가는 모든 아이템에 존재하고, 급습 발생 시점과 경매 모드에 관계없이 결정론적으로 계산할 수 있다.
- **필수 검증:** 합계보다 1 적음, 정확히 같음, 1 많음, 중복 클릭, 두 경매 모드.
- **영향:** REQ-BM-003, STAB-001/WP-03.

### DEC-003: 경찰 체포 페널티와 영속화

- **상태:** APPROVED
- **결정일:** 2026-08-21
- **결정자:** PM
- **문제:** PRD의 전액 몰수와 과거 DEV 가이드의 50% 몰수가 충돌하고, 현재 구현은 세션 화면만 0으로 만들고 커리어에는 반영하지 않는다.
- **결정:** 시간 초과 체포 시 현재 세션의 유동 현금을 100% 몰수하여 `careerCash_after = 0`으로 영구 저장한다.
- **영향 범위:**
  - 입장료와 체포 전 소비는 복구하지 않는다.
  - 체포된 암시장 세션에서 획득한 아이템은 영구 보관함에 커밋하지 않는다.
  - 체포 이전부터 보유한 영구 보관함 아이템과 업적은 몰수하지 않는다.
  - 체포된 세션은 `totalGamesPlayed`에 포함하지만 승리와 정상 완주로 취급하지 않는다.
  - 저장 완료 후 로비로 이동하며 새로고침 후에도 현금 0이 유지되어야 한다.
  - 파산 여부는 현금 0과 남아 있는 영구 보관함 평가액을 사용해 기존 파산 기준으로 다시 계산한다.
- **검토한 대안:** 현금 50% 몰수, 현재 라운드 현금만 몰수, 영구 보관함까지 전부 몰수.
- **선택 이유:** 암시장 고위험 정체성을 유지하면서 과거 커리어 수집품까지 삭제하는 과도한 처벌은 피한다.
- **필수 검증:** 보관함 없음·있음, 저장 후 새로고침, 로비 복귀, 파산 경계, 중복 타이머.
- **영향:** REQ-BM-003, STAB-001/WP-03.

### DEC-008: TASK 최종 승인과 릴리즈 승인 분리

- **상태:** SUPERSEDED (GOV-002)
- **결정일:** 2026-08-21
- **결정자:** 사용자 승인 / PM 반영
- **문제:** QA가 인수 조건과 회귀 검증을 완료한 뒤 PM이 같은 TASK를 다시 승인하면 형식적 중복 절차와 대기 시간이 발생한다.
- **결정:** QA가 개별 TASK의 최종 완료 권한을 가지고 직접 `DONE`으로 처리한다. PM은 개별 TASK를 재승인하지 않고 마일스톤·릴리즈만 승인한다.
- **TASK 상태:** `BACKLOG -> READY -> IN_PROGRESS -> DEV_COMPLETE -> QA_IN_PROGRESS -> DONE`.
- **릴리즈 상태:** `PLANNED -> RELEASE_CANDIDATE -> PM_RELEASE_APPROVED -> RELEASED`.
- **예외:** 인수 조건 변경, 결함 수용, 범위 이관 또는 제품 정책 결정이 필요하면 QA는 `PRODUCT_DECISION_REQUIRED`로 PM에게 요청한다.
- **선택 이유:** 역할별 판단을 중복하지 않으면서 QA 독립성과 PM의 제품·릴리즈 책임을 함께 유지한다.
- **대체:** `GOV-002`가 `DONE`을 모든 역할군에 개방했다. 릴리즈 승인을 QA 검증과 분리하는 원칙은 유지한다.
- **영향:** AGENTS.md, 공통 운영 규칙, PM·DEV·QA 역할, QA Plan, TASKS, PROJECT_STATE.

### DEC-009: 탈출 시 긴급 대출 상환

- **상태:** APPROVED
- **결정일:** 2026-11-09
- **결정자:** PM
- **문제:** `QD-04`. `ESCAPED` 정산이 `loanRepaymentAmount`를 차감하지 않아 대출 원금과 이자가 세션 현금으로 남는다. 대출 후 탈출하면 상환 없이 현금을 확보하는 경제 익스플로이트가 가능하다.
- **결정:** `ESCAPED`도 `NORMAL`과 같은 순서로 상환한다.
  - `endingCash = player.cash - (hasTakenLoan ? loanRepaymentAmount : 0)`로 계산한다.
  - 이후 `NORMAL`·`ESCAPED` 공통 종료 디버프를 한 번 적용한다.
  - 상환 후 음수 잔액은 탕감하지 않고 기존 파산 판정으로 처리한다.
- **검토한 대안:** 탈출 시 대출 기능 비활성화, 원금만 회수, 상환액 0으로 고정.
- **선택 이유:** 이미 발생한 부채를 결과별로 다르게 처리하면 자금 보존 계약이 깨진다. `NORMAL`과 `ESCAPED`가 같은 상환 규칙을 쓰면 검증과 멱등성이 단순해진다.
- **필수 검증:** 대출 후 탈출의 상환 전·정확히 일치·상환 후 경계, 상환 후 음수와 파산, 중복 탈출, 새로고침 후 잔액.
- **영향:** REQ-CORE-002, REQ-BM-003, `STAB-002/QD-04`.

### DEC-010: 감정 비용의 권위

- **상태:** APPROVED
- **결정일:** 2026-11-09

- **문제:** `QD-08`. `Item.appraisalCost`는 아이템·룸 티어에 따라 $300~$5,000으로 차등되어 있지만, 감정 store와 UI는 `APPRAISAL_CONFIG.COST` $500만 사용한다. 표시·차감·테스트의 권위가 다르다.

### DEC-011: 보존 상태·잭팟 평가의 단일 계약

### DEC-012: 런타임·배포 경로

- **상태:** APPROVED
- **결정일:** 2026-11-09
- **결정자:** 사용자 지시 / QA_DEVOPS 반영
- **문제:** 저장소가 Node 22 CI와 Node 26 로컬을 함께 사용해 `localStorage` Web Storage 경고와 `@types/node` 불일치가 생겼고, 모든 런타임 이미지 경로가 `/assets/...` 루트 절대 경로라 하위 경로 배포에서 404가 발생할 수 있었다. 개발 의존성에는 Vite·Vitest 보안 취약점이 남아 있었다.
- **결정:** Node.js 26 이상과 npm 11 이상을 `.nvmrc`·`engines`·CI에 고정한다. 테스트는 `NODE_OPTIONS=--no-experimental-webstorage`를 사용한다. 배포 경로는 `VITE_BASE_PATH`로 주입하고 기본값은 `/`로 둔다. 런타임 문자열 경로는 `assetUrl()`을 사용하며, Vite가 처리하는 HTML·CSS 경로는 `base`에 맡긴다. `npm audit` 전체·프로덕션 0건을 유지한다.
- **검토한 대안:** Node 22 LTS 유지, 하위 경로 배포 포기, 런타임 경로를 모두 상대 경로로 수동 치환.
- **선택 이유:** Node 26은 보안 패치와 현재 로컬·CI 기준을 통일한다. `VITE_BASE_PATH`와 `assetUrl()` 조합은 루트·하위 경로를 같은 소스로 지원하고, Vite의 HTML·CSS 변환과 충돌하지 않는다.
- **영향:** `package.json`, `.nvmrc`, `.github/workflows/qa.yml`, `vite.config.ts`, `src/services/assetService.ts`, `src/data/`, `index.html`, `vercel.json`, `README.md`, `REPO-001`.
- **후속 검증:** fresh clone `npm ci`→typecheck→test→build, 루트·하위 경로 preview 404 0, Lighthouse SEO 1.00, `npm audit` 0건. Vercel 실제 배포는 프로젝트 재개 후 확인한다.

## 운영 규칙

- PM이 제품 정책과 거버넌스 결정을 승인한다.
- DEV가 기술 대안과 영향을 정리하지만 제품 정책을 단독 결정하지 않는다.
- QA_DEVOPS는 검증 결과와 결함 영향을 기록하고, `OPEN` 결정을 임의로 해석하지 않는다.
- `DONE`은 모든 역할군이 가능하지만, 결정되지 않은 `OPEN` 사항을 완료로 덮지 않는다.
- 결정이 바뀌면 기존 행을 삭제하지 않고 `SUPERSEDED`로 남긴다.
- 승인된 결정은 관련 PRD, TASK, 기술 명세에 역링크한다.
