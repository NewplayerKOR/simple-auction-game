# 개발 상세 제약 및 인계 기준

> **역할 절차:** [`../roles/DEV.md`](../roles/DEV.md)  
> **상태:** ACTIVE  
> **최종 수정일:** 2026-11-09
> **관련 문서:** [`PRD.md`](./PRD.md), [`DECISIONS.md`](./DECISIONS.md), [`ARCHITECTURE.md`](./ARCHITECTURE.md), [`DATA_SCHEMA.md`](./DATA_SCHEMA.md)

## 1. 이 문서의 범위

이 문서는 구현 시 지켜야 할 기술적 제약을 기록한다. 제품 정책과 TASK 상태는 각각 PRD, DECISIONS, TASKS를 따른다.

## 2. 착수 전 확인

- 활성 TASK가 `[ ]` 또는 `[-]`이고 목적·범위·인수 조건이 준비됐는지 확인한다.
- 관련 결정이 `APPROVED`인지 확인한다.
- 관련 FSM·데이터 계약이 최신인지 확인한다.
- 현재 재현 결과와 테스트 범위를 기록한다.

경제·암시장 구현은 승인된 `DEC-001`~`DEC-004`를 따른다. 세부 FSM·데이터 계약이 TASK에 준비되지 않았다면 제품 결정을 직접 코드로 해석하지 않고 `.md/specs/`의 최신 계약 또는 PM 결정을 기다린다.

## 3. 필수 구현 불변식

### 경제

- 설명되지 않는 현금 생성·소실 금지
- 세션 잔액과 커리어 잔액의 단일 정산 경로
- 입장료, 낙찰, 감정, 대출, 뇌물, 저주, 파산의 중복 반영 금지

### FSM과 타이머

- 결과 확정은 멱등이어야 한다.
- 타임아웃, 수동 제출, 모달 종료가 동일 라운드를 중복 정산하지 않아야 한다.
- 상태를 종료 상태로 바꾼 뒤 후속 타이머 호출은 무시해야 한다.
- 비동기 콜백은 현재 게임·라운드·FSM을 다시 확인해야 한다.

### 더치 경매

- 구매자·잔액·현재 상태를 검증한 후 락을 확정한다.
- 실패한 구매 시도 때문에 틱 엔진이 멈추지 않아야 한다.
- AI는 숨겨진 `realValue`, `isFake`를 직접 판단 근거로 사용하지 않는다.

### 영속화

- 커리어에 영향을 주는 결과는 저장 완료 전 로비 복귀로 유실되지 않아야 한다.
- 새로고침 후 결과가 동일해야 한다.
- 저장 버전 변경은 `.md/specs/MIGRATIONS.md` 기록과 함께 수행한다.

## 4. 개발 완료 인계

- 실행·검증·배포 명령의 상세 절차는 루트 [`DEVELOPMENT.md`](../../DEVELOPMENT.md)를 따른다. 이 문서는 구현 불변식과 인계 기준만 소유한다.
- 다음을 활성 TASK 작업 기록에 남긴다.

- 변경 파일과 동작
- 추가·변경한 테스트
- 실행한 명령과 결과
- 브라우저에서 확인한 흐름
- 실패하거나 수행하지 못한 검증
- QA 재현 절차

DEV 자체 검증 완료는 독립 QA 또는 TASK `DONE`을 자동으로 의미하지 않는다. `DONE`은 모든 역할군이 가능하지만, DoD와 검증 증거를 충족해야 한다. 릴리즈 승인은 PM이 별도로 판정한다.
