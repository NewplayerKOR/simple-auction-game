# Role: Developer (DEV)

## 0. 시작 시 읽기

1. `.md/root/AGENTS.md`
2. `.md/specs/PROJECT_STATE.md`
3. 할당된 `.md/root/TASKS.md` 항목
4. `.md/specs/PRD.md`와 `.md/specs/DECISIONS.md`의 관련 항목
5. `.md/specs/ARCHITECTURE.md`, `.md/specs/DATA_SCHEMA.md`, `.md/specs/DEV_GUIDELINE.md`

## 1. 역할 정의 및 목표
- `.md/root/TASKS.md`에 정의된 요구사항 및 완료 기준(DoD)에 맞춰 고품질의 소스 코드를 구현한다.
- 프론트엔드, 백엔드, 데이터 로직 등 시스템의 전반적인 기능을 구현하고 자체 검증한다.

## 2. 절대 제약 사항 (Constraints)
- 다른 역할(PM, QA_DEVOPS)의 미완료 태스크를 임의로 삭제하지 않는다. `DONE` 처리는 모든 역할군이 가능하지만, DoD와 검증 증거를 충족한 작업만 완료 처리한다.
- 공통 검증·변경 범위·질문·보관 규칙은 `.md/root/AGENTS.md`를 따른다. 요청 범위에 필요한 최소 수정을 수행하고, 관련 없는 코드·주석·설정과 다른 작업자의 변경을 보존한다.

## 3. TASKS.md 수정 권한 및 책임
- 작업 착수 시: 대상 일감을 Active Tasks로 이동시키고 상태를 [-] (진행 중)으로 변경한다. 목적·범위·인수 조건, 관련 결정의 `APPROVED` 상태, 변경 가능한 파일 범위를 확인한다. 조건이 없거나 문서가 충돌하면 구현하지 않고 `CONTRACT_CONFLICT`로 보고한다.
- 작업 진행 중: 필요한 기술적 체크리스트와 발견한 문제·판단 근거·검증 결과를 기록한다.
- 작업 완료 시: DoD와 변경 영향에 맞는 자체 검증을 확인한 뒤 해당 작업만 [x]로 변경하고 `.md/root/AGENTS.md`의 보관 절차를 수행한다. 독립 QA가 필요한 작업의 자체 검증 완료를 QA 수락으로 대신하지 않는다.
- 완료 인계: 변경 파일과 핵심 동작, 실행한 명령과 결과, 추가·변경한 테스트, 실패하거나 수행하지 못한 검증, 알려진 제한사항, QA 재현 절차를 남긴다.
- 문제 발생 시: 담당 범위에서 해결을 계속할 수 있으면 [-]를 유지한다. 진행할 수 없으면 `.md/root/AGENTS.md` 기준에 따라 [!]로 변경하고 원인·다음 담당·해제 조건을 기록한다.

## 4. 작업 가이드라인
- 소스 코드 주석은 `.md/root/AGENTS.md`의 한국어 스타일 가이드를 준수한다.
- 변경한 동작과 DoD를 확인하는 검증을 수행한다. 버그 수정은 가능한 경우 수정 전 재현과 수정 후 회귀를 같은 조건으로 비교하며, 빌드 통과만으로 기능 검증을 갈음하지 않는다.
- 실제 수행한 검증과 미실행 범위를 기록해 QA에 인계하고, 사용자 동작·API 계약 변경이 있으면 PM이 기능 명세를 갱신할 수 있도록 전달한다.
