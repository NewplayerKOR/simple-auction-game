### 7.1 공통 세션·영속화 계약

#### 단일 작성자

- `SIMPLE_AUCTION_CAREER_V2`의 쓰기는 커리어 영속화 계층 한 곳만 수행한다.
- 게임 정산, 도감 아이템 해금, 업적 해금, 티켓 지급, 누적 게임 수 갱신은 하나의 커밋으로 계산하고 한 번 저장한다.
- `useCodexStore`와 결과 화면은 영속 프로필을 다시 쓰지 않고 커리어 저장 결과를 조회·표시한다.
- LocalStorage 한 키의 JSON 교체를 현재 런타임의 원자적 저장 경계로 사용한다. 실제 DB 트랜잭션 또는 서버 원장을 구현한 것으로 표현하지 않는다.

#### 세션 식별과 멱등성

```typescript
type CareerSessionOutcome = 'NORMAL' | 'ESCAPED' | 'ARRESTED' | 'ABANDONED';

interface ActiveCareerSession {
  sessionId: string;
  tier: RoomTier;
  entryFee: number;
  sessionCashStart: number;
  ticketConsumed: 0 | 1;
  status: 'ACTIVE';
}

interface CareerSettlementCommand {
  sessionId: string;
  outcome: CareerSessionOutcome;
  endingCash: number;
  acquiredItems: Item[];
  isWinner: boolean;
  unlockedAchievementIds: string[];
}
```

- 룸 입장 성공과 동시에 고유 `sessionId`를 만들고 입장료·필요 티켓 차감 및 `activeSession` 생성을 한 번 저장한다.
- 정산 명령의 `sessionId`가 현재 `activeSession.sessionId`와 같을 때만 적용한다.
- 성공 시 `activeSession`을 제거하고 마지막 정산 영수증을 저장한다. 동일 명령 재호출은 `ALREADY_APPLIED`, 다른 세션의 오래된 명령은 `STALE_SESSION`으로 거부한다.
- 중간 새로고침으로 경매 스냅샷을 복구할 수 없으면 세션을 `ABANDONED`로 닫는다. 이미 저장된 입장료·티켓 차감은 유지하고, 저장되지 않은 세션 아이템·승리·보상은 커밋하지 않는다.
- 금액은 현재 코드 계약에 맞춰 정수 달러를 사용한다. `NaN`, 무한대, 음수가 허용되지 않는 입력 비용은 저장 전에 거부한다.

### 7.2 WP-01 경제 정산 계약

#### 자금 불변식과 순서

1. 입장 직전 `careerCash_before`를 읽는다.
2. `sessionCash_start = careerCash_before - entryFee`를 계산하고 프로필에도 같은 값을 저장한다.
3. 경매 세션은 `sessionCash_start`를 플레이어 시작 현금으로 사용한다. 입찰·감정·대출·보조금·뇌물은 이 세션 잔액에 각각 한 번만 반영한다.
4. 정상 종료 시 `endingCash = player.cash - loanRepayment`를 먼저 계산한 뒤 종료 시 발동하는 저주를 정확히 한 번 반영한다.
5. `careerCash_after = endingCash_after_debuff`로 **교체**한다. 기존 `careerCash`와 더하지 않는다.
6. 진품 획득 아이템과 상태를 보관함에 합친 뒤 `careerNetWorth_after = careerCash_after + vaultTotalValue_after`로 재계산한다.
7. 파산·룸 게이팅·승급 판정은 같은 `careerCash_after`와 `careerNetWorth_after`만 사용한다.

#### 결과별 커밋

| 결과 | 현금 | 이번 세션 아이템 | 게임 수/승리 | 티켓·정상 완주 |
| :--- | :--- | :--- | :--- | :--- |
| `NORMAL` | 최종 세션 잔액으로 교체 | 진품만 커밋 | 게임 수 +1, 1위면 승리 +1 | WP-05 규칙 적용 |
| `ESCAPED` | 탈출 직전 확정 잔액으로 교체 | 급습 전 확정 아이템만 커밋 | 게임 수 +1, 승리 +0 | 지급 없음 |
| `ARRESTED` | 0으로 교체 | 이번 세션 아이템 전부 폐기 | 게임 수 +1, 승리 +0 | 지급 없음 |
| `ABANDONED` | 마지막으로 저장된 입장 후 커리어 현금 유지 | 커밋 없음 | 증가 없음 | 지급 없음 |

#### DEV 인수 조건

- 무입찰·전부 유찰 브론즈 게임은 시작 현금과 종료 현금이 같고 현금이 복제되지 않는다.
- 입장료가 있는 룸은 무거래 종료 시 `careerCash_after = careerCash_before - entryFee`다.
- 대출 원금은 세션에서 한 번 증가하고 상환액은 종료 시 한 번 차감된다.
- `finishGame`·결과 화면 재렌더·로비 복귀를 반복해도 같은 `sessionId`의 현금·게임 수·보관함이 다시 변하지 않는다.
- 음수 종료 잔액과 새로고침 경계가 별도 테스트로 고정된다.

### 7.3 WP-02 비밀경매 단일 확정 계약

#### FSM

```text
SEALED_BID_ACTIVE
  -- submit(amount) | timeout --> SEALED_BID_FINALIZING
SEALED_BID_FINALIZING
  -- submissions frozen ------> SEALED_BID_REVEALED
SEALED_BID_REVEALED
  -- close reveal ------------> ROUND_SETTLING
ROUND_SETTLING
  -- settlement committed ----> ROUND_REVEAL / NEXT_ROUND_CHECK
```

- `submit`과 `timeout`은 동일한 `finalizeSealedRound(roundResolutionId, humanAmount?)` 명령을 호출한다.
- 첫 호출만 `SEALED_BID_ACTIVE -> SEALED_BID_FINALIZING` 전이에 성공한다. 이 전이와 동시에 카운트다운을 중지한다.
- 유효한 수동 입찰은 잔액 이내의 양수다. 미입력·0·음수·잔액 초과·비정상 숫자는 `0(FOLD)`으로 정규화한다.
- 플레이어 제출 1개와 봇 제출 3개를 `SEALED_BID_FINALIZING`에서 한 번만 생성하고 동결한다. 공개 모달은 동결된 스냅샷만 읽는다.
- `SEALED_BID_REVEALED`에서는 타이머 틱, 재제출, 봇 재생성, 결과 재정렬을 모두 무시한다.
- 모달 닫기는 `roundResolutionId`당 한 번만 라운드 정산을 호출한다. 이중 클릭과 React 재렌더는 결과를 바꾸지 않는다.
- 동률 우선순위는 이번 안정화에서 기존 참가자 순서를 보존하되, 그 순서를 명시적 `participantOrder`로 저장하여 런타임 정렬 안정성에 의존하지 않는다.

#### DEV 인수 조건

- 수동 제출과 같은 틱의 타임아웃이 경합해도 제출 스냅샷과 낙찰 결과가 하나다.
- 공개 모달을 5초 이상 열어 두어도 입찰 배열·낙찰자·현금이 변하지 않는다.
- 모달 닫기 연속 클릭, `tickTimer` 재호출, 동일 명령 재호출이 모두 멱등이다.
- 전원 `0`이면 최고 입찰자 없이 유찰된다.

### 7.4 WP-03 경찰 결과 영속화 계약

#### 급습 공통

- 급습 시작 시 영어/비밀경매 타이머와 더치 틱을 일시 중지하고 `RAIDED` 외 경매 명령을 차단한다.
- 급습마다 `raidId`를 발급한다. `escape`, `bribe`, `timeout/arrest` 중 첫 유효 명령만 `RAIDED`를 종료할 수 있다.
- 결과 저장이 성공하기 전에는 로비로 이동하지 않는다. 저장 실패 시 같은 `raidId`로 재시도 가능하며 추가 차감·추가 몰수하지 않는다.

#### 탈출

- 현재 라운드의 미확정 입찰·아이템은 폐기한다.
- 급습 이전 라운드에서 확정된 세션 현금과 진품 아이템으로 `ESCAPED` 부분 정산한다.
- 기존 영구 보관함·업적·티켓을 유지하고, 승리·완주·티켓 보상은 지급하지 않는다.

#### 뇌물

- `itemPrice = currentItem.startingBid`, `totalCost = 5_000 + itemPrice`다.
- `cash >= totalCost`일 때만 활성화한다. 정확히 같은 잔액은 허용한다.
- 첫 유효 명령에서 `totalCost`를 한 번 차감하고 현재 아이템을 플레이어에게 한 번 지급하며 봇 경쟁을 종료한다.
- UI에는 뇌물 $5,000, 아이템 시작가, 총비용을 분리해 표시한다.
- 뇌물 처리 후 해당 라운드의 정상 공개/다음 라운드 흐름으로 복귀한다.

#### 체포

- 5초가 만료되면 같은 `raidId`의 `ARRESTED` 정산을 한 번 실행한다.
- `careerCash = 0`, `careerNetWorth = 기존 영구 보관함 평가액`으로 저장한다.
- 이번 세션에서 획득한 아이템은 모두 폐기하고, 세션 시작 전 보관함과 업적은 유지한다.
- `totalGamesPlayed`만 1 증가하며 승리·정상 완주·티켓 지급은 없다.

- 확률 테스트는 `Math.random`을 고정하거나 RNG를 주입해 경계값을 결정론적으로 검증한다.

### 7.6 WP-05 티켓 보상·소모 계약

- `NORMAL` 결과에서 현재 룸이 `GOLD` 또는 `DIAMOND`이면 순위와 관계없이 티켓 1장을 지급한다.
- `ach-blind-master`가 기존 프로필에는 없고 이번 정산에서 처음 해금되면 티켓 1장을 지급한다. 같은 정산에서 룸 완주 조건도 만족하면 두 출처는 독립적이므로 총 2장이다.
- 브론즈·실버·암시장, `ESCAPED`, `ARRESTED`, `ABANDONED`에는 룸 완주 티켓이 없다.
- 순자산 $100,000 미만에서 티켓으로 암시장에 입장하면 입장료와 티켓 1장을 같은 저장에서 차감한다.
- 순자산 $100,000 이상이면 티켓을 보유해도 소모하지 않는다.
- 입장료 부족, 파산, 다른 게이팅 실패에는 티켓을 소모하지 않는다.
- 티켓 지급과 업적 최초 판정은 WP-01의 단일 커밋에 포함하며 별도 `grant` 호출로 중복 저장하지 않는다.

### 7.7 WP-06 더치 공정성·락 계약

#### 클레임 순서

1. 현재 상태가 `DUTCH_DROPPING`이고 같은 `sessionId`·`roundId`인지 확인한다.
2. 현재 아이템, 구매자, 공개 가격 스냅샷이 존재하고 `buyer.cash >= price`인지 검증한다.
3. 검증 성공 후에만 클레임 락을 비교 후 교체한다. 실패한 구매자는 틱을 멈추지 않는다.
4. 락 성공자는 가격·구매자·`roundResolutionId`를 동결하고 틱과 예약 콜백을 중지한다.
5. 동일 라운드의 나머지 클레임과 바닥가 콜백은 무시하고 정산을 한 번만 실행한다.

#### 공개 정보 기반 AI

- 더치 AI의 인지 가치 기준은 `(estimatedMin + estimatedMax) / 2`와 룸별 오차, 페르소나, 공개 시장 이벤트뿐이다.
- `realValue`, `isFake`, 감정하지 않은 진위, 비공개 플레이어 정보는 WTP·반응 지연·구매 여부에 사용하지 않는다.
- 지연 콜백은 `sessionId`, `roundId`, `buyerId`를 캡처하고 실행 시 현재 라운드와 다시 비교한다.

#### 바닥가

- 가격이 바닥가에 처음 도달하면 바닥가를 한 번 게시하고 `500ms`의 최종 구매 창을 연다.
- 최종 구매 창에서 유효 클레임이 없을 때만 `DUTCH_FLOOR_PASSED`로 전이한다.
- 바닥가 유찰, 사용자·봇 클레임, 경찰 급습, 로비 복귀는 모든 더치 타이머와 예약 콜백을 정리한다.

#### DEV 인수 조건

- 존재하지 않는 구매자와 잔액 부족 구매자의 시도 후에도 가격 하락이 계속된다.
- 동시에 예약된 사용자/봇 클레임 중 한 명만 낙찰되고 한 번만 차감된다.
- AI 테스트에서 `realValue`와 `isFake`만 바꿔도 같은 RNG 입력의 판단 결과가 변하지 않는다.
- 바닥가 게시 직후 500ms 안의 유효 구매는 성공하고, 창 종료 후 구매는 실패한다.

### 7.8 WP-08 릴리즈 버전·30종 표기 계약
