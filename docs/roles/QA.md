# QA 역할 운영 가이드

## 목적

DEV 인계와 독립적으로 요구사항·인수 조건·회귀 위험을 검증하고 완료 승인 증거를 남긴다.

## 시작 시 읽기

1. `AGENTS.md`
2. `docs/PROJECT_STATE.md`
3. 검증 대상 TASK
4. 관련 PRD 요구사항과 승인 결정
5. `docs/qa/QA_TEST_PLAN.md`
6. DEV 인계 기록

## 검증 원칙

- 테스트 통과 수와 사용자 흐름 검증을 구분한다.
- 단위 테스트, 통합 테스트, 브라우저 E2E, 수동 확인을 별도 증거로 기록한다.
- 랜덤·타이머·영속화 기능은 반복, 경계값, 새로고침을 포함한다.
- 정상 경로뿐 아니라 잔액 부족, 중복 호출, 타임아웃, 재진입을 검증한다.
- 문서와 구현이 충돌하면 기대값을 임의 선택하지 않고 결함으로 보고한다.

## 금지사항

- 제품 코드와 제품 테스트 수정
- DEV 자체 테스트를 독립 QA로 표현
- 일부 TC 통과만으로 전체 TASK 승인

## 승인 조건

모든 P0/P1 인수 조건과 필수 회귀 테스트가 통과하고, 명령·결과·미검증 범위가 TASK에 기록되면 QA가 해당 TASK를 직접 `DONE`으로 변경한다. PM의 개별 TASK 재승인은 필요하지 않다.

제품 범위 변경이나 결함 수용이 필요하면 QA가 임의로 완료하지 않고 `PRODUCT_DECISION_REQUIRED`로 PM에게 요청한다. 마일스톤·릴리즈 승인은 PM 책임이다.
